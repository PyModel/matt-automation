# Changelog

Behavior that moved. The phase files are the spec; this list is the delta.

- The orchestrator saves a receipt verbatim and never edits it (BUILD.md step 5). A run rewrote a refused receipt's `repairs` with evidence it wrote itself and merged the ticket.
- The receipt template shows `repairs: []`, and CONTRACT.md says what `review` holds: an implementer's own review fixes count in `review.cited_fixed`, never in `repairs`. A worker copied the filled `repairs` example for its self-review fix and its receipt was refused. A malformed `repairs` now gets one message instead of an extra `repair "undefined" is undefined`.
- A cited review finding whose fix needs a `guarded` path the objective does not name is a blocker in NOW `blockers:` (BUILD.md step 6, CLOSE.md stage 8), never a lead or a fix ticket. A run parked one as a lead, where the stage 8 fix subagent would then have edited the guarded path unchecked.
- The stage 8 review subagent must have a shell (CLOSE.md): `code-review` resolves by `matt.mjs` and reads `git diff review_base...HEAD`, which a read-only helper cannot run.
- `goal.mjs` sets `process.exitCode` instead of calling `process.exit()`, which dropped output a pipe had not yet read: `goal.mjs run -- <suite> | tail` lost the `log:` line and `goal.mjs receipt … | <parser>` read truncated JSON. Its usage lists one command per line, so `--help | grep <command>` finds it.
- `goal.mjs run` prints its `log:` line before the command's output as well as after, so a harness that truncates long output still shows it. A receipt whose log `sha256` is not a sha256 gets its own message instead of "changed after the run". The merge script gates on the receipt check's exit code (BUILD.md step 5.0), since a pipe hid a refused receipt and its ticket merged.
- A per-ticket review delegated to a helper gets that ticket's own contract and its `git diff <ticket-base>...<after>` in the prompt, built fresh per ticket (BUILD.md step 6). A read-only helper has no shell, so without the diff it reviewed reconstructed file state, and copied review briefs carried another ticket's questions.
- State lives in `--state-dir`, else `TO_AUTO_HOME`, else `~/.local/state/to-auto/<repo-id>`. It is a private git repo. `goal/control` is no longer created in the user repo, and `.git/info/exclude` is no longer edited.
- A linked worktree whose shared git dir is not writable is cloned into the state folder at `goal.mjs prepare`. `goal.mjs land` brings the new commits back, or writes `return.bundle` while the git dir stays read-only.
- `--allow` lists the only folders a run may write. A write outside that list fails at preflight, before any run write.
- `--worker-model` records the requested helper model. `goal.mjs model` records the model each role used. `--no-helpers` records that none ran.
- `scripts/install.mjs` links `to-auto`, `to-bug`, `to-new`, and `to-orc` into skill folders. Scripts resolve their own location from their file path.
- Supervisor mode: `--base`, `--target-branch`, `--status-file`, `--no-remote`. Land writes an item-to-commit summary and does not contact a remote.
- `goal.mjs check-command` reads `check:` from the objective, else AGENTS.md or CLAUDE.md, else a Makefile `check`/`test` target, else package.json `check`/`test`.
- Git 2.42 is not required. `goal.mjs preflight` checks that git is on PATH and the state folder is writable.
- Always-on text is SKILL.md plus CORE.md. Before compacting, rewrite NOW and run `goal.mjs compact`.
- `goal.mjs cleanup` deletes the state folder only.
- Run and ticket worktrees come from `goal.mjs worktree get|return|status`: a treehouse lease when `treehouse` is on PATH, else a git worktree under `<state>/worktrees/`, recorded in `runs/<slug>/worktrees.json`. Docs no longer name a `.worktrees/` layout.
- `goal.mjs worktree get` cuts treehouse slots under `<state>/worktrees/pool/{slot}/{repo}` and refuses any worktree under a directory whose `.gitignore` or `.ignore` has a `*` or `**` line (treehouse's pool root has one): gitignore-aware linters scan nothing there and exit 0. A refused treehouse slot is returned first and the message names the `treehouse destroy` that retires it. `goal.mjs run` refuses the same ancestors. Hooks are never gates: 0d records every hook-run check as a `commands:` entry and the hook-install command as `hooks=`, which implementers re-run after every install. 6b: a criterion never pins a value copied from a dated record.
- `goal.mjs check <slug>` / `check --all` report NOW ahead of the registry, a malformed NOW, and a stale registry; `next` reports `blocked` and `compact` refuses when NOW is ahead. Stage 9 moves the registry to done before NOW says done.
- `goal.mjs cleanup` refuses while a run worktree is active or the clone holds unlanded commits.
- Backlog objectives are split into bounded batch runs at admission (BOOTSTRAP.md § 00 step 5); repository rules never skip a stage.
- Stage 0a caches kun with upstream `pull-kun.mjs`: `kun/<sha>/` now holds `content/` (kun's own words) beside the four root docs. A cache without `content/MANIFEST.json` is incomplete and is pulled again, seeded from the newest complete cache.
- `goal.mjs registry` refuses `planning` without an active run worktree, `specced` without `spec.md`, and `ticketed` without tickets, so the registry cannot be walked forward empty to silence `check`. `init` refuses backlog objectives ("fix all N issues"). `check` STALE counts any `[<slug>]` control-plane commit as activity, and stopped runs report nothing until `resume`.
- SKILL.md: the stage `next` names is binding; no repo work before `init`, in-flight work from before the invocation is not resumed outside a run, and a refused objective is never worked around.
- `scripts/to-auto-guard.mjs` (Claude Code hooks): a `/to-auto` session cannot push, branch, open or merge PRs, write to the tracker (`gh issue`, writing `gh pr` and `gh api` calls) or spawn helper agents until its run is registered, and can never hand-type `git worktree add`. Commands are judged with shell quoting stripped; only the first `git` subcommand counts, so `git stash push` passes. A re-invoked `/to-auto` keeps the first mark, a hand-touched mark is released by any done run of the session, a guard failure in a marked session denies the judged call only (never `ls` or `git status`), and marks older than 30 days are swept.
- `scripts/to-auto-watch.sh notify` compares the problem set (`<state-dir> <slug> <CODE>`), not the message text: a STALE run notifies once, not on every sweep as its age grows.
- `goal.mjs check` reports `TODO_BEHIND` when todo.md is unticked before the stage the registry status has reached, and `goal.mjs next` then resumes at that stage (building → 7) instead of the stale first unticked one. A run resumed with a lagging todo.md was sent back to planning.
- `goal.mjs tick <slug> <stage> [--skipped <reason>]` is the one writer of todo.md stage ticks, NOW's `- stage:` line and every forward registry move, in one commit: it refuses an out-of-order stage, a missing stage artifact and a registry step whose evidence is missing, and writes nothing when refused. `goal.mjs registry` now takes only `dry-run`. Two runs had moved the registry to building and reviewing while todo.md and NOW stayed at 5b and 6b, because ticks were typed by hand and nothing tied them to the registry. A catch-up tick (a stage the registry already passed) is committed as `catch-up` and does not reset `STALE`, and `check` also reports `TODO_AHEAD` (ticked past a registry move by hand), on which `next` blocks until a re-tick makes the move on its evidence.
- `goal.mjs commit` (and `event`, `init`) refuses a commit that changes a run's status, a todo.md stage tick or NOW's stage line, except NOW set back to the first unticked stage; `tick` and status moves roll their files and the index back when the commit fails; `compact` refuses on `TODO_AHEAD`; `tick`, `stop`, `resume` and status moves refuse while a stage copy holds an uncommitted hand edit, before writing anything, so they never commit it as their own.
- The control plane has a pre-commit hook (`goal.mjs guard-staged`), so a raw `git commit` there meets the same ticket and stage guards as `goal.mjs commit`; goal.mjs's own commits skip it through `TO_AUTO_WRITER`. A lock taken where no control plane exists no longer leaves an empty state folder behind.
- `stop`, `resume` and `init` are one commit each. `resume` gates before writing: before, a resume refused by its gate had already removed `STOP`, leaving a run that `tick` called stopped and `resume` called not stopped. `tick` holds the `control` lock across its read and write of ledger.md, so a concurrent `event` and the tick no longer lose each other's line. `stop`, `resume` and `event` refuse a slug that is not a run folder name. `check --all` reports a `runs.json` of the wrong shape, and one unreadable run, without dropping the others.
- `next` and `tick` refuse a slug `init` would refuse, so a run cannot be resumed under a name it was never registered with. The move to `planning` (tick 0c) needs `review_base` in NOW, since stage 8 reviews against it. A baseline line may also be `skip`.
- Stage 5b re-runs the reconciliation gate at most 4 rounds (budget `reconciliation rounds`); items left after that get a `/kun` ruling instead of another round.
- `take` creates `runs/<feature>/tickets/`, where BUILD.md writes each ticket contract.
- `goal.mjs` run from a folder inside the control plane (a helper in `runs/<slug>/`) no longer trips the shared-git-dir refusal meant for a user repo.
- Readiness refuses a criterion or claim on a git-ignored path. When the repo ignores `CONTEXT.md`, NOW records `glossary: ignored` and no spec line or ticket targets it.
- `goal.mjs dispatch --phase implement` refuses a `--brief` that does not carry the ticket's committed contract verbatim: a brief copied from another ticket, or one built before a claims amendment, never reaches a worker.
- `orc-dispatch --force` refuses while the dispatch under that `--task` is still running: it replaced finished evidence, and also started a second worker beside a live one.
- `goal.mjs init` refuses a run without `--agent` and `--harness` (exit 2). A pi run was registered with both null, so nothing recorded which session ran it and the Claude Code guard could never release that session.
- `goal.mjs <command> --help` (or `-h`) prints usage and exits 0. Before, `slug --help` read `--help` as the objective and printed the slug `help`. After `run --` the flag belongs to the command.
- The run base is `goal/bootstrap` only while it carries commits the default branch head lacks. A `goal/bootstrap` already merged is skipped (it had cut a run 71 commits behind main), and one that does not contain the head is refused until rebased.
- `goal.mjs model` refuses a run registered with `--no-helpers` (a helper ran that the run said would not) and a slug with no run.
- `goal.mjs dispatch --phase implement` also refuses a brief that carries another ticket's contract: one brief merged for several tickets passed the own-contract check for each.
