8. **Final review, fresh context.** The registry is `reviewing` (the tick of 7 moved it). The orchestrator holds every assumption that shaped the code, so it does not review. Dispatch one **review subagent** with a shell (it runs `matt.mjs resolve`, `git diff` and the debt grep; a read-only helper such as `pi --read-only` cannot, so it reviews reconstructed file state, not the diff) whose brief is only: `review_base` (BOOTSTRAP.md § 0c), the run branch, the spec path, `GLOSSARY.md`, the ledger path, and "load `code-review` by path (`node ROOT/scripts/matt.mjs resolve code-review`) and run it against `<review_base>` with `<spec path>`, briefing its sub-agents per PITFALLS.md (code-review rows); then `defensive-design` in Review mode over `review_base...HEAD` for every module at Tier 2 or 3; load neither skill again; return the two reports verbatim", then LEDGER.md § Subagent contract. Save its final message verbatim to `runs/<slug>/review.md` and commit it. Hand every cited finding (a standards rule, a smell plus hunk, a spec line, a defensive-design finding with evidence) whose fix stays off ungranted `guarded` paths (one that needs such a path is a blocker, CORE.md) to one **fix subagent** (implement-spec step 7) in the run worktree; log uncited leads. Then one independent, targeted **re-verification** subagent checks each fixed finding against the resulting snapshot and runs the suite; save its final message to `runs/<slug>/verify.md` and commit it. Both briefs end: "Finish with one JSON object: `{ "verdict": "ship" | "no-ship", "head": "<git rev-parse of the branch you read>", "open": [<each finding still open>] }`." (A review that cites nothing to fix ends with it and needs no verify.md.) Then `node ROOT/scripts/goal.mjs verdict <slug>` writes `final-verdict.json` from those files: it refuses `no-ship`, any open finding, a `head` that is not the run branch's tip, a `review_base` that is not NOW's, and a third rewrite of verify.md (stage 8 is one review, one fix pass, one re-verification; past that, `goal.mjs stop <slug> "<open findings>"` and carry them to a follow-up run). A `final-verdict.json` written any other way is refused at commit and never counts. `goal.mjs tick <slug> 10` (the move to `done`) refuses unless the target's tip is still `review_head`: anything merged after the review sends the run back through this stage, never around it.
