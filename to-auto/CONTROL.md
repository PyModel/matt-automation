# Control plane: private history, outside the repo

Every run on a repo shares one **control plane**: the state folder `goal.mjs control` prints. Chosen by `--state-dir`, else `TO_AUTO_HOME`, else `~/.local/state/to-auto/<repo-id>` (`repo-id` is a hash of the shared git dir, so every worktree of one clone shares it and a different clone does not). It is its own git repo. It holds the tracker, every run's ledger, the kun cache, the run registry, and the quarantine list. It is **committed after every write** (history is kept). It is **not a branch of the user repo** and it is **never merged** into one: run branches carry only code.

```
<state>/                          # private git repo; not goal/control
  runs.json                       # run registry: slug, objective, run_id, started, status, agent, harness, workerModel, helpers
  tracker/<feature-slug>/spec.md
  tracker/<feature-slug>/issues/NN-<slug>.md
  runs/<slug>/ledger.md  todo.md  log.md  bugs.md  findings.md  spec.md  notes/  tickets/NN.status.md  final-verdict.json  retro.md  models.json
  runs/<slug>/STOP                # kill switch (committed so it survives everything)
  kun/<sha>/ENTRY.md TOOLS.md OPINIONS.md VOICE.md content/  # pull-kun.mjs cache of kunchenguid/kun at <sha>
  quarantine.json                 # flaky tests at base, per base commit
  workspace.json                  # prepare: checkout, or a clone when the shared git dir is not writable
  supervisor.json                 # --base, --target-branch, --status-file, --no-remote
  locks/                          # not committed
  clone/                          # not committed; the S3 workspace
  gc.log
```

## Locks

Locks are the one thing not committed: `mkdir` directories under `<state>/locks/`, next to the private history, so a linked worktree does not need to write the shared git dir. Take them only through `ROOT/scripts/goal.mjs`, which holds the lock for the whole transaction, writes the holder's pid, waits up to 2 minutes for a live holder, and breaks a lock older than 10 minutes whose holder is dead:

- `goal.mjs commit -m "[<slug>] <what>" <file>...` stages exactly those control-plane files and commits them under the `control` lock. This is the only way to commit to the control plane. Each ticket field has one writer, and `commit` refuses any other: a new ticket enters well-formed as `blocked` or `ready-for-agent`; the Status line changes only through `take` and `status`; `**Claims amended:**` and `**Waived:**` lines only through `claim` and `waive`; the Claims line by hand only before dispatch; `**From review:**` never after creation; and a dispatched ticket (`in-flight`, `needs-human`, `done`) never changes a criterion (checkbox lines, ticks aside): new work goes to a new ticket or NOW `leads:`, and a criterion proven wrong is released with `goal.mjs waive`. A raw `git commit` that goes around it is still caught: `contract`, `dispatch` and `status … done` re-read the ticket against its dispatch commit.
- `goal.mjs claim <feature> <NN> <exclusive|shared-regenerate> <path>... -- "<why>"` widens a ticket's claims after a claims breach (BUILD.md § Claims amendment): tracker issue, contract and ledger in one commit, refused for a guarded path, a new overlap inside the run, or a third amendment.
- `goal.mjs waive <feature> <NN> <criterion number> [--carried-to <NN>] -- "<why>"` releases one acceptance criterion (numbered from 1 in ticket order) of an in-flight ticket that its committed receipt shows `fail` or `not-run` and that is proven wrong or unmeetable here: a `**Waived:** <criterion> — <why>` line in the ticket and a ledger event, one commit. `--carried-to` names the open ticket that now holds the criterion verbatim (files another in-flight ticket owns), and is checked. The criterion and its box stay as written; the receipt check and `status … done` no longer require it (CONTRACT.md § The receipt check). Refused for a ticket not in flight, a criterion the receipt passes, a second waiver on one ticket (the ticket is wrong: re-plan it), or when it would leave no criterion in force.
- `goal.mjs contract <NN.goal.md> --worktree <wt> --ticket <ticket.md>` checks a compiled contract before dispatch (CONTRACT.md § The contract), including, from history, that the ticket has a dispatch commit (`[<feature>] ticket NN → in-flight`, written only by `take`/`status`), that its criteria are the dispatched ones, and that its claims equal the dispatched ones plus its `**Claims amended:**` lines.
- `goal.mjs dispatch <feature> <NN> --worktree <wt> -- <orc-dispatch args>` is the only way a pi worker gets a ticket (BUILD.md § Implementer backend): it refuses a ticket not in flight or whose committed contract fails the `contract` checks, then runs to-orc's dispatcher with `--run-dir <git-common-dir>/to-orc/<feature>/t<NN>` and `--repo <wt>` set by itself, so a ticket's cycles and budget live in one run directory. `--poll` only reads, so it skips the checks.
- `goal.mjs worktree get <slug> [NN]` prints the run's (or ticket NN's) worktree path, creating it once: a `treehouse get --lease --no-fetch --lease-holder <slug>` slot switched to the branch when `treehouse` is on PATH (`TO_AUTO_TREEHOUSE` overrides; an installed treehouse that fails is an error, never a fallback), else `git worktree add` under `<state>/worktrees/`. A branch already checked out is recorded as `borrowed`. `goal.mjs worktree return <slug> [NN]` refuses a dirty worktree, detaches and returns a treehouse slot or removes a git worktree, and is safe to repeat; `goal.mjs worktree status <slug>` prints `runs/<slug>/worktrees.json`. Records are written under the `worktrees` lock and committed.
- `goal.mjs check <slug>` is read-only and exits 1 on any problem: `NOW_AHEAD` (NOW's `- stage:` id needs a registry status the run has not reached: 00–0c bootstrapping, 0d–5b planning, 6–6b specced, 7 building, 8–10 reviewing, `done` done), `NOW_MALFORMED` (no or unknown stage id), `STALE` (an active run with no `[<slug>]` control-plane commit, of any kind, for `--stale-hours`, default 2). Done, dry-run and stopped runs report nothing; `resume` puts a run back under check. `check --all [--state-root <dir>]` sweeps every control plane under `~/.local/state/to-auto` (plus `TO_AUTO_HOME`), one `<state-dir> <slug> <CODE> <message>` line per problem, silent on exit 0. `next` reports `blocked` and `compact` refuses on `NOW_AHEAD`. External triggers run it, because a run that has left the pipeline never calls goal.mjs itself: `scripts/to-auto-watch.sh hook` (a SessionStart `compact` hook: prints the current repo's problems into the session) and `scripts/to-auto-watch.sh notify` (a scheduled job: a desktop notification when the problem set changes). On Claude Code, `scripts/to-auto-guard.mjs` (hooks `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse` on `Bash|Agent|Task|Skill`) enforces the entry rule in the harness: a session that starts with `/to-auto` (or calls the to-auto skill) is marked, and while its repo has no active run the guard denies `git push`, a new branch (`branch <name>`, `switch -c`, `checkout -b`, `--orphan`), tracker writes (`gh issue` and `gh pr` subcommands that write, `gh api` with a non-GET method or parameters) and helper agents, judging each command with shell quoting stripped; a hand-typed `git worktree add` is denied even with a run active. It is not a sandbox: a command that hides its words from a regex gets through. In a marked session a guard failure (goal.mjs unloadable, unreadable state) denies the call it was judging and no other: goal.mjs is loaded only for a call a rule names, so a broken goal.mjs never stalls `ls`, `git status` or `goal.mjs init`. A session that cannot be marked has its `/to-auto` prompt blocked. Marks older than 30 days are swept on the next mark. The mark is dropped once a run that session registered (`init --agent <session id>`, which the guard prints) is done and none is active; a run it stopped keeps the session marked, so stopping is never a way around the pipeline. Other harnesses have no equivalent hook; there `check --all` is the backstop.
- `goal.mjs run -- <command>` runs one validation command through the shell in the current worktree, keeps its output under `<git-common-dir>/goal-logs/` ending in a footer with the command, exit code, HEAD and whether the tree was dirty, passes the exit code through, and prints `log: {"path", "sha256"}` for the receipt (CONTRACT.md § The receipt).
- `goal.mjs event <slug> <stage> "<text>"` appends one `- HH:MM [stage] text` line to `runs/<slug>/ledger.md`, stamped with the real local clock, and commits it. Every ledger event goes through it.
- `goal.mjs take <feature> <n>` flips up to `n` frontier tickets to `in-flight` under `frontier-<feature>` and commits them; `goal.mjs status <feature> <id> <status> [--landed <sha>] [-- <reason>]` moves one ticket and commits it. The moves are the whole lifecycle: `blocked` → `ready-for-agent` | `stuck`; `ready-for-agent` → `in-flight` | `blocked` | `stuck`; `in-flight` → `done` | `stuck` | `needs-human`; `needs-human` → `in-flight` (a resume, not a new dispatch) | `stuck`; `stuck` → `ready-for-agent` (after its re-plan, so the next dispatch is a fresh baseline) | `blocked`; `done` is final. `stuck` and `needs-human` need a reason, which stays on the line (`**Status:** stuck: <reason>`). `ready-for-agent` → `in-flight` passes the same gate as `take` (a clean claims gate, the ticket on the frontier). `done` needs `--landed <sha>`, the commit that carries the ticket on the integration branch, and refuses unless the committed `tickets/<NN>.receipt.md` passes the receipt check against git at its own head (a temporary worktree) with conclusion `completed`, the ticket still matches its dispatch commit, and `<sha>` contains the receipt head or carries the same change (`git patch-id`, so a squash merge counts); then it ticks every box not waived. A merge that skipped the check, or landed something other than what the receipt proves, cannot close the ticket. Both, and `claim`, refuse a ticket or contract with uncommitted edits other than ticked boxes: any other change to a ticket (a new ticket, a criterion moved or added) is committed first with `goal.mjs commit` and a message saying why, so it never rides in under a status line.
- `goal.mjs with-lock <name> -- <cmd...>` runs one command under any lock (`integration`, `bootstrap`, `registry`, or `frontier-<feature>` on a GitHub tracker). Locks are re-entrant for that command, so it may call `goal.mjs commit` itself.
- File arguments are paths inside the state folder (`runs/<slug>/ledger.md`); a path from the current directory that lands inside it works too.

| Lock | Guards |
|---|---|
| `control` | creating the state folder (`goal.mjs control`); every commit to it (`goal.mjs commit` stages only the named files, so concurrent agents' half-written files stay out). |
| `integration` | merging ticket branches into run branch head (rebasing, fast-forwarding, removing ticket worktrees) |
| `bootstrap` | creating `goal/bootstrap` |
| `frontier-<feature>` | reading the frontier and flipping a ticket to `in-flight` |
| `registry` | reading and editing `runs.json` |

## Rules

- `goal.mjs control` creates the control plane once, under the `control` lock: `git init` in the state folder, first commit `Init to-auto control plane`. It does not create a branch in the user repo and it does not edit `.git/info/exclude`. It is idempotent. Git 2.42 is not required. `goal.mjs preflight` checks the remaining requirements (git on PATH, a writable state folder, and the allow list) and refuses to start with a clear message when one fails.
- `goal.mjs prepare` records the workspace. A primary checkout is used as-is. A linked worktree whose shared git dir is not writable is cloned into `<state>/clone` (`git clone --no-local`, so the clone does not hardlink into the read-only git dir). `goal.mjs land` fast-forwards those commits back when the git dir is writable, and writes `<state>/return.bundle` when it is not.
- `--allow <path>` (repeatable) is the only set of folders the run may write. preflight checks every planned write against it and fails before the first write.
- Supervisor flags, stored by `goal.mjs supervise`: `--base <commit>`, `--target-branch <name>`, `--status-file <path>`, `--no-remote`. `goal.mjs land` appends a summary of `item sha` lines to the status file. `--no-remote` makes `goal.mjs` refuse `git push`, `pull`, `ls-remote`, and fetch or clone of a non-local URL.
- `--worker-model <model>` on `init` (or as a global flag) records the requested helper model. `goal.mjs model <slug> <role> <model>` records the model that role actually used. `--no-helpers` records `helpers: none`.
- `goal.mjs check-command --objective "<text>"` prints the check command: a `check:` in the objective, else the same line in `AGENTS.md` or `CLAUDE.md`, else `make check` or `make test`, else `npm run check` or `npm test`.
- `goal.mjs cleanup` deletes the state folder. It refuses (exit 1, nothing deleted) while any `runs/*/worktrees.json` record is `active` or `<state>/clone` holds a branch tip the repo does not have; otherwise it removes a worktree whose path is inside that folder, and it does not delete branches or edit ignore files.
- Every control-plane write is committed with `goal.mjs commit`, subject `[<slug>] <what>`; the user reads the factory's history with `git -C <state> log`. A file only one agent writes (its own `runs/<slug>/` files, its ticket status file) needs no lock for the write itself; a file several agents write is written only by the command that owns it: `runs.json` by `init`, `registry`, and `stop`; tracker tickets by `take` and `status`, which read, write, and commit under the ticket lock.
- The state folder is shared by every run and every subagent on this clone; it is the only path that crosses run boundaries.
- The private history is not pushed by a run. With `--no-remote`, it is not fetched either.

## Run registry (`runs.json`)

```json
[{"slug":"add-login","objective":"…","run_id":3,"started":"2026-09-07T13:40:00.000Z","status":"building","agent":"<session id>","harness":"<harness name>"}]
```

`run_id` is the next unused integer; it scopes ports and database names (BOOTSTRAP.md § 0d). `goal.mjs` owns the file: `slug` derives the slug (lower-case, non-alphanumerics to `-`, collapsed, at most 40 chars; `--new` picks the next free `-2`, `-3` for a deliberate re-run), `init` appends the entry (and refuses a backlog objective such as "fix all N issues": BOOTSTRAP.md step 5), `registry <slug> <status>` moves it one step along `bootstrapping` → `planning` → `specced` → `ticketed` → `building` → `reviewing` → `done`, or to `stopped` or `dry-run` from anywhere, refusing a skipped step, `planning` without an active run worktree in `runs/<slug>/worktrees.json` (stage 0c), `specced` without `runs/<slug>/spec.md`, `ticketed` without a ticket in `tracker/<slug>/issues` or a ticket table in `todo.md`, `reviewing` while any ticket in `tracker/<slug>/issues` is neither `done` nor `stuck` (a parked or needs-human ticket is marked `stuck` with its reason first), and `done` unless the committed `runs/<slug>/final-verdict.json` says `"verdict": "ship"` for a `target` branch whose tip is its `review_head` (CLOSE.md stage 8), so nothing lands after the final review unreviewed; `stop` writes `STOP` and sets `stopped`, and `resume` removes `STOP` and restores the status the stop replaced. The entry records the `agent` and `harness` that `init` was given; `--gc` judges liveness by them. The duplicate-run check is BOOTSTRAP.md § 0. `--stop` without a slug stops the single running entry, or reports the list when there are several.

## Tracker grammar (local tracker)

The only status line the frontier parser accepts, exactly:

```
**Status:** ready-for-agent | in-flight | done | stuck | blocked | needs-human
```

plus `**Blocked by:** 01, 03` or `None` (a parenthetical or a title after a number is ignored, so to-tickets' `None (can start immediately)` and `01 (reason)` parse) and `**Claims:** exclusive: a/b.ts, c/ ; shared-regenerate: pnpm-lock.yaml ; guarded: .github/**`, optionally `**Claims amended:** +<paths> (<kind>): <why>` lines, which only `goal.mjs claim` writes, `**Waived:** <criterion> — <why>` lines, which only `goal.mjs waive` writes, `**From review:** NN` on a fix ticket born from ticket NN's review (a chain deeper than two fix generations is malformed, BUILD.md step 6), and optionally `**Capability:** advanced/high` (tier `lightweight | standard | advanced` / intensity `low | medium | high`; absent means `standard/medium`; any other value makes the ticket malformed). Every checkbox line in a ticket is one acceptance criterion, which `goal.mjs receipt` matches by text. A claim is a file, a directory ending in `/`, or a directory ending in `/**`. Frontier = `ready-for-agent` tickets whose every blocker is `done`. `goal.mjs frontier <feature>` computes it, reports each ticket's resolved `capability`, and reports every malformed ticket and every pair of unordered open tickets whose `exclusive` claims overlap; it returns an empty frontier while any ticket is malformed. `cross_run` lists overlaps between this run's open tickets and open tickets of other unfinished runs in `runs.json`; they never block (separate run branches), but whichever run the user merges second will conflict there.
