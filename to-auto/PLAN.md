Every ticket also carries a `**Capability:**` line (CONTRACT.md § Capability). Strip `ready-for-agent` from the parent spec after publishing.

## Ready source (route `ready`)

Stages exist to produce an agent-ready source; when the objective already names one, they are skipped, not re-run. Applies when the objective points at an approved spec, ticket, or tracker issue this repo holds (a path or a full reference), and that source passes CONTRACT.md § Readiness as a whole, bar the base (stage 0c recorded `review_base`). A raw issue someone else filed is triaged first (FLOWS.md row 1); a label alone never makes a source ready.

- Stage 1 still explores the repo and writes `findings.md`; every requirement in the source becomes an R<n>.
- Stages 2 to 4b are ticked `(skipped: ready source <path or ref>)`. Research runs only if `findings.md` has an open Q.
- Stage 5 copies the source into `spec.md` verbatim, with a header naming where it came from, and publishes it to the tracker as the parent. 5b runs as written, reconciling against `findings.md`.
- Stage 6: a source that is one ticket becomes ticket `01` as it stands, plus its claims, capability, and demo path; a spec goes through to-tickets as usual. 6b runs as written.
- Any readiness box that fails turns this path off: log which one, and the run continues at stage 2 with the source as its first finding.

The bug fast path below is the same move for a finished diagnosis.

## Single-ticket feature (route `feature`)

Require one specified observable behaviour (including relevant edges), an existing public test seam, available fixtures, and one Tier 0/1 claim set. Any open product or external question, new boundary, dependency, migration, or guarded path means full planning instead.

- **4:** Replace the interview with the usual defensive-design check, loaded with `matt.mjs resolve defensive-design --slug <slug>`. In `log.md`, record a `[4]` decision naming `single-ticket feature`, the requirement, seam, tier, and claims. The tick of 4 checks both.
- **4b:** Read that decision; tick with `--skipped single-ticket-feature`.
- **5/5b:** Use the normal spec template, briefly; reconcile as usual.
- **6:** Write only ticket `01`, with no blockers. Skip the slicing quiz.

Other rules and gates are unchanged. If later evidence rules this path out, use `goal.mjs stop <slug> <reason>`.

## Bug fast path (route `bug`)

Applies when `diagnosing-bugs` finished with: one command red before any theory, a regression test red then green, a named seam, a post-mortem, and the fix confined to modules that fit one `exclusive` claim set at Tier 0 or 1. Then stages 4 to 6 are skipped:

- `spec.md` is the post-mortem: symptom, red command, root cause, seam, regression test path, tier, files touched. Publish it to the tracker as the parent. Then `goal.mjs tick` 4 to 6 in order with `--skipped bug fast path` (`spec.md` is stage 5's artifact; the tick of 5b moves the registry to `specced`).
- Exactly one ticket `01`: acceptance criterion = the regression test command; demo path = the red command going green; claims = the files the fix touched; tier from `defensive-design` Implement mode over the diff; capability from CONTRACT.md § Capability (no line means `standard/medium`). Run the 6b gate (the criterion is red at the base commit by construction; verify by running it there), then `goal.mjs tick <slug> 6b`, which moves the registry to `ticketed` and `building`.
- Stage 7 has nothing to dispatch: write ticket `01`'s receipt from the on-ramp's own evidence, check it with `goal.mjs receipt` against the run worktree and `review_base`, `goal.mjs take` ticket `01`, run the full suite against the per-test baseline, then `goal.mjs status <slug> 01 done --landed <run branch head>` (it re-checks the receipt and ticks the ticket), `goal.mjs tick <slug> 7` (the registry moves to `reviewing`), and go to stage 8, whose diff from `review_base` includes the stage 2 fix.

Any of these turn the fast path off and the run continues at stage 4 with the post-mortem as its first finding: no seam found, more than one claim set, Tier 2 or 3, a `guarded` path, the regression test needs a fixture the repo lacks, or the post-mortem names a design cause (`improve-codebase-architecture` lead). `/to-bug` pins this route and skips the classification.
